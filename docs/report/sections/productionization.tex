\chapter{Model Optimization and Productionization}

\section{Optimization for the Edge}
Industrial monitoring often requires deployment on edge gateways (e.g., Raspberry Pi or NVIDIA Jetson) where resources are limited. We optimized our pipeline for these environments.

\subsection{Feature Dimensionality Reduction}
As discussed in Section 4, reducing the feature set from 104 to 40 decreased the memory footprint and CPU utilization by over 50\% with minimal accuracy loss. This allows the feature extraction script to run in near real-time on low-power devices.

\section{Public Deployment and Service Workflow}
To demonstrate the practical utility of our system, we deployed the champion XGBoost pipeline as an interactive web service.

\subsection{Hugging Face Listener Service}
The production model is hosted on \textbf{Hugging Face Spaces} (\url{https://huggingface.co/spaces/KarimmYasser/machine-sound-listener}). This deployment utilizes a \texttt{Gradio} interface to allow users to upload \texttt{.wav} files and receive real-time anomaly diagnostics. The service encapsulates the full \texttt{fast\_features} extraction engine and the serialized XGBoost model, providing a blueprint for low-latency industrial monitoring dashboards.

\subsection{Service Workflow}
The internal inference service operates through a simple workflow:
\begin{enumerate}
    \item \textbf{Receive:} Accepts a \texttt{.wav} file payload via a POST endpoint.
    \item \textbf{Preprocess:} Normalizes and standardizes the audio.
    \item \textbf{Extract:} Computes the Top 40 acoustic manifold features.
    \item \textbf{Predict:} Passes features to the XGBoost model or spectrogram to the EfficientNet model.
    \item \textbf{Response:} Returns the class label (e.g., "Machine 2 Abnormal") and a confidence score.
\end{enumerate}

\section{Containerized Deployment via Docker}
To ensure strict environment replication across different industrial servers, we utilized \textbf{Docker} for our final submission. The containerized architecture addresses the complexity of deploying a hybrid Python/Rust pipeline.

\subsection{Docker Engine Configuration}
The provided \texttt{Dockerfile} (based on \texttt{python:3.11-slim}) automates the entire system setup:
\begin{enumerate}
    \item \textbf{Native Toolchain:} Installs the Rust compiler and \texttt{build-essential} to compile the feature extraction extension.
    \item \textbf{Dependency Management:} Orchestrates the installation of both Python (NumPy, XGBoost, Librosa) and Rust crates.
    \item \textbf{Optimized Entrypoint:} The container is configured to run the \texttt{infer.py} script by default, accepting a mounted data volume for seamless batch processing.
\end{enumerate}

\section{Public Web Interface: Hugging Face Spaces}
For stakeholder review and live demonstrations, we deployed the model to \textbf{Hugging Face Spaces} using the Docker SDK.

\subsection{The Machine Sound Listener App}
The live application (accessible via the team's space) features a modern \textbf{Gradio} web interface. This cloud-native deployment utilizes our high-performance Rust backend to provide real-time diagnostics:
\begin{itemize}
    \item \textbf{Live Waveform Upload:} Users can upload any \texttt{.wav} recording from the factory floor.
    \item \textbf{Instant Inference:} The system classifies the machine type and status (Normal/Abnormal) with an associated confidence score.
    \item \textbf{Performance Monitoring:} The application displays the backend engine status (Rust vs. Librosa) to demonstrate our optimization achievements.
\end{itemize}

\section{Reliability and Monitoring}
The production service includes logging and performance monitoring. By tracking the distribution of confidence scores, we can detect "Concept Drift"—where the machine's acoustic signature slowly changes over years due to natural aging—and trigger a retraining cycle.

\subsection{Automated Performance Diagnostics}
To ensure the reliability of every training run and model update, our pipeline includes automated diagnostic generation. For every training iteration, a high-resolution confusion matrix is generated and exported to the \texttt{outputs/} directory.

Combined with per-class F1-scores, these diagnostics form the basis for our quality assurance gate before any model is promoted to the edge gateways.
